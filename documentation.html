with Integrated Testing Pipelines

Final Year Project Documentation | 4th Year Computer Science

What This Project Does

This system automatically takes your code from a developer's machine all the way to a live production server. Every time a developer pushes code, the system:

  1. Builds the application
  2. Runs all automated tests (unit, integration, end-to-end)
  3. Scans for security vulnerabilities
  4. Packages it into a Docker container
  5. Deploys to staging for verification
  6. Deploys to production
  7. Monitors performance in real-time

Phase 1: CI/CD Pipeline Design

What is CI/CD?

CI (Continuous Integration) = Every code push is automatically built and tested.

CD (Continuous Delivery/Deployment) = Tested code is automatically deployed to servers.

Together, they eliminate manual steps between writing code and running it in production.

Phase 2: Application Code (Spring Boot)

About the Application

The application is a Task Manager REST API — a simple CRUD (Create, Read, Update, Delete) application that manages tasks. It is built with Spring Boot, which is the most popular Java web framework.

What is Docker?

Docker packages your application and ALL its dependencies (Java, libraries, config) into a single portable unit called a container. This container runs identically on any machine — your laptop, staging server, or production server.

Dockerfile Explained (Multi-Stage Build)

# STAGE 1: Build the app using Maven
FROM maven:3.9-eclipse-temurin-17 AS build     ← Start with Maven + JDK image
WORKDIR /app                                    ← Set working directory
COPY pom.xml .                                  ← Copy dependencies file
RUN mvn dependency:go-offline -B                ← Download all dependencies
COPY src ./src                                  ← Copy source code
RUN mvn clean package -DskipTests -B            ← Build the JAR file

# STAGE 2: Run the app (smaller image)
FROM eclipse-temurin:17-jre-alpine              ← Lightweight Java runtime only
WORKDIR /app
COPY --from=build /app/target/*.jar app.jar     ← Copy JAR from build stage
EXPOSE 8080                                     ← Open port 8080
ENTRYPOINT ["java", "-jar", "app.jar"]          ← Run the application

Docker Commands

# Build the Docker image
docker build -t automated-deployment-system .

# Run the container
docker run -p 8080:8080 automated-deployment-system

Prometheus

What is Prometheus?

Prometheus is a monitoring tool that scrapes metrics from your application every few seconds. It collects data like: how many requests were made, how fast they were, how much memory is used, and if any errors occurred.

Phase 6: Security (DevSecOps)

What is DevSecOps?

DevSecOps = Development + Security + Operations. It means security checks are automated into the pipeline, not done manually after deployment. Security is "shifted left" — caught early in the development process.

  DevSecOps in Our Pipeline:

  Code Written ─> OWASP Check ─> SonarQube Scan ─> Docker Build ─> Trivy Scan ─> Deploy

SonarQube

What is SonarQube?

SonarQube is a static code analysis tool. It reads your source code (without running it) and finds: bugs, security vulnerabilities, code smells (bad practices), and duplicate code.

Running SonarQube Locally

# Start SonarQube (included in docker-compose)
docker-compose up -d sonarqube

# Wait for it to start (takes ~1 minute)
# Open http://localhost:9000 (login: admin / admin)

# Run analysis
mvn sonar:sonar -Dsonar.host.url=http://localhost:9000 -Dsonar.login=admin -Dsonar.password=admin

Trivy Container Scanner

What is Trivy?

Trivy scans Docker images for known security vulnerabilities (CVEs). It checks the OS packages and application dependencies inside the container.

# Scan the Docker image
docker run --rm aquasec/trivy image automated-deployment-system:latest

How to Run the Project

Option 1: Run Locally (Just the App)

Requires only: JDK 17 + Maven

# Build the project
mvn clean install

# Run the application
mvn spring-boot:run

# App runs at http://localhost:8080
# Swagger UI at http://localhost:8080/swagger-ui.html
# H2 Console at http://localhost:8080/h2-console

Option 2: Run with Docker Compose (Full Stack)

Requires only: Docker Desktop

# Start everything (app + MySQL + Prometheus + Grafana + SonarQube)
docker-compose up -d

# Check all services are running
docker-compose ps

# Stop everything
docker-compose down

Option 3: Deploy to Kubernetes

Requires: Docker + Minikube + kubectl

# Start Minikube
minikube start

# Build Docker image inside Minikube
eval $(minikube docker-env)
docker build -t deploymentpipeline/automated-deployment-system:latest .

# Deploy all Kubernetes resources
kubectl apply -f k8s/

# Check deployment status
kubectl get all -n deployment-system

# Get the app URL
minikube service app-service -n deployment-system --url

Option 4: GitHub Actions (Cloud CI/CD)

Requires: GitHub account only

# Push code to GitHub
git add .
git commit -m "Deploy automated deployment system"
git push origin main

# Go to GitHub → Actions tab → Watch pipeline run automatically!
